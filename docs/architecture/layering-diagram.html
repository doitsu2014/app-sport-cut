The rule

Source-code dependencies point inward. An outer layer may depend on an inner one; an inner layer may never depend on an outer one, and a use case never depends on the gateway that implements its port. Runtime calls run the other way, through a port.

sportcut-service → sportcut-api. The use cases live in sportcut-api, which is an ordinary library — no FFI, no generated bindings — but which is parked in adapters/, so the check sees two adapters. The Flutter client links no Rust, so nothing about the client depends on where this crate sits. Removed by moving it to core/use-cases/; then the edge is adapter → use case and the exception is deleted. Recorded in tools/check-layering.sh with the same condition.
